# SillyTavern load test — zhino-status

Loaded without zns errors: **yes**. The panel rendered all three cases, and zhino’s floating button stayed on screen beside it.

No changes were made to `zhino-status/src/index.js` or `dist/index.js`. `node --check` passed on both, and the two files are still identical.

## Setup

- SillyTavern `1.19.0` (`release` @ `06bde93`), cloned to `/workspace/st-test`. Bound to `127.0.0.1:8000` only (`listen: false`, whitelist `127.0.0.1` and `::1`, `basicAuthMode: false`, `whitelistDockerHosts: false`).
- Browser auto-launch, extension auto-update, model auto-download, and downloadable tokenizers were turned off so startup stayed local and did not rewrite the cloned extension.
- Tavern Helper `JS-Slash-Runner` `4.11.3` at `st-test/public/scripts/extensions/third-party/JS-Slash-Runner` (this build still loads global extensions from that folder).
- `zhino-status/dist` served with CORS at `http://127.0.0.1:8787/index.js`.
- Playwright drove headless Google Chrome (`/usr/bin/google-chrome`), viewport 1440×900. No LLM and no API key.

On the first page load the onboarding dialog was dismissed with persona name `Tester`. Later runs found onboarding already completed.

Both global scripts were written through `TavernHelper.replaceScriptTrees`, not by clicking the script editor. Both were enabled:

- `zns`: `import 'http://localhost:8787/index.js'`
- `zhino`: `import 'https://cdn.jsdelivr.net/gh/sillytavner-jpg/zhino-script@v5.2.9/dist/index.js'`

Iframes: `TH-script--zns--zns-status-bar`, `TH-script--zhino--zhino-script`.

Character `ZnsTester` was created with `TavernHelper.createCharacter` and opened with `SillyTavern.getContext().selectCharacterById`.

## Fixes

None in the status script.

One host shim was required in the SillyTavern checkout, not in zhino-status. Tavern Helper 4.11.3 externalizes lodash as the bare global `_`, and SillyTavern 1.19.0 no longer assigns that global (`SillyTavern.libs.lodash` only). Without it the extension throws `ReferenceError` before any script iframe runs. `initLibraryShims` in `st-test/public/lib.js` now sets `window._ = lodash` when `_` is missing. Webpack served that bundle at `/lib.js`.

## Limitations

- Messages were inserted with Tavern Helper (`replaceVariables`, `createChatMessages`). Nothing was generated by a model.
- The MVU library itself was not installed. The test used MVU-shaped `stat_data` (`[82, "战斗消耗后的灵力"]`, `"96/140"`, `"6/12"`) through chat variables and latest-message variables. `Mvu.getMvuData` was not on the page.
- The `<status>` block stays visible in the chat bubble. zns reads it and does not strip it. Hiding it would be a SillyTavern regex, which this run did not add.
- Only the same-origin Tavern Helper srcdoc iframe was tested. A cross-origin iframe that cannot touch the parent document was not.
- zhino was loaded from jsDelivr (`v5.2.9`, about 1.9 MB) plus its CDN imports. A CDN failure would show up as a zhino load error, not a zns error.
- Servers were stopped after the run. Nothing was published or pushed.
